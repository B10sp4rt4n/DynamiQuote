# Declaración explícita y recorrido comercial

Oportunidades muestra + Nueva oportunidad. El alta captura cliente activo del tenant y nombre; asigna responsable desde la sesión. No requiere cotización ni monto. Guarda actor, fecha y un identificador de intento en intake_metadata, sin migraciones. Un reintento con el mismo identificador recupera el resultado; otros datos/actor se rechazan. La asignación de folios usa el mismo advisory lock transaccional que el creador de cotizaciones.

Tras guardar, Continuar: crear cotización abre el formulario con cliente, nombre y oportunidad existente preseleccionados. La selección se valida en servidor por tenant, vendedor, cliente y estado abierto; el escritor de cotizaciones vuelve a validarla. Un enlace indisponible no abre un alta nueva. La tabla de oportunidades ofrece Crear cotización y muestra Por estimar para altas explícitas sin importes de propuestas.

La secuencia 1 Oportunidad → 2 Cotización → 3 Propuesta usa números, textos y color: azul actual, verde con check para pasos anteriores acreditados, gris pendiente/anterior, ámbar con explicación ante errores del alta. Se muestra en Oportunidades, alta, cotizador y detalle de propuesta. Los enlaces de pasos permiten navegación directa. El resultado comercial y las reglas de autorización/envío existentes conservan su autoridad.

Validación actualizada: 528 pruebas generales aprobadas; 38 omitidas por condiciones (incluidas tres de concurrencia ejecutadas por separado). Ensayo de PostgreSQL 18.6 nativo: 10 pruebas aprobadas de alta explícita e intake existente. Seis reintentos simultáneos producen una sola oportunidad; ocho altas mezcladas con el escritor de cotizaciones conservan folios consecutivos sin duplicación. Ensayo HTTP local con identidad bootstrap: render del alta, POST con actor de sesión, recuperación de reintento y preselección en Cotizaciones aprobados. Dos pruebas de interfaz en jsdom verifican números, etiquetas, error ámbar y continuidad al negocio creado.

Reproducción nativa: instalar embedded-postgres@18.6.0-beta.19 en un directorio temporal, fuera de las dependencias del producto; definir EMBEDDED_POSTGRES_MODULE con la ruta a dist/index.js y ejecutar node scripts/check_explicit_opportunity.mjs. COTIZA_HTTP_CHECK=1 agrega el ensayo HTTP con fixtures y servidor Next local. El script crea una base vacía en loopback; nunca toma DATABASE_URL productiva. COTIZA_BROWSER_CHECK=1 mantiene el entorno sintético abierto para un recorrido manual. Finaliza con SIGINT. TypeScript, ESLint dirigido y compilación Next.js forman parte del control de liberación.

Límite: interfaz probada con jsdom y HTML servido por Next con actor bootstrap; no acredita apariencia por píxeles ni sesión real de Clerk. El navegador compartido no pudo alcanzar el servidor local.
